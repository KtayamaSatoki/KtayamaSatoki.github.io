電験学習サイト 全体仕様書

文書版数：2.0
対象：問題管理・学習・採点・履歴・苦手分析・バックアップ・削除・ホーム画面・ダークモード機能
実装方式：HTML・CSS・JavaScriptによる単一静的Webアプリケーション（SPA構成）
保存方式：IndexedDB（データ保存）、localStorage（テーマ設定）
開発状況：全主要機能のコード統合、SPA画面切り替え、およびダークモード対応完了

1. システム概要
1.1 目的
登録した電験の学習問題を繰り返し解き、回答結果と分野別の成績を確認できる、個人利用向けの学習サイトを提供します。
以下の一連の操作を対象とします。
ホーム画面 → 問題JSONの取り込み → 内容確認 → 出題対象設定 → 学習 → 回答確定・採点 → 解説確認 → リザルト確認 → 苦手分析
あわせて、問題の改訂・削除、全データのバックアップ・復元、不要な分野の安全な削除に対応します。

1.2 基本方針
・個人利用を前提とし、ログインを不要とする。
・有料サーバー・有料データベース・AI APIを必須としない。
・問題や学習記録は、利用するブラウザー内に保存する（IndexedDB）。
・外部の生成AI等で作成した問題を、所定のJSON形式で取り込む。
・問題内容の正確性は、利用者が確認する。
・元問題の編集・削除によって、保存済みの学習内容を変更しない。
・保存直前に競合を検査し、古い画面からの意図しない上書きを防ぐ。
・ホーム画面および上部ナビゲーションを基点としたSPA（Single Page Application）構成とし、機能ごとに独立した操作画面を提供する。
・利用環境や目の疲労に配慮し、ライトモードとダークモードの切り替えに対応する。

1.3 対象科目
科目は、次の4科目に固定します。
・theory：理論
・power：電力
・machine：機械
・regulation：法規

分類は科目 → 分野の2階層とします。トピックは初期版の必須項目に含めません。

2. 実装範囲と現在の状況
2.1 実装済みの機能
・問題・分野のJSON取り込み（schemaVersion: 1）
・取り込み前の形式検査、既存データとの版番号・内容比較
・登録済み問題の一覧・検索・絞り込み・プレビュー
・確認状態（未確認／確認済み／要修正）と出題対象設定の変更
・学習条件の選択と前回条件の自動復元
・5択および一問一答による出題と自動採点
・回答確定・途中再開・二重回答防止
・今回のリザルト表示・過去リザルト閲覧（科目ごと最新10回保持）
・科目ごとの直近100回答による分野別・形式別苦手分析（5区分判定）
・全保存領域（全6ストア）のバックアップJSON出力
・検査付きの全置換復元（事前バックアップ検証付き）
・JSON形式による問題内容の直接編集（版番号更新・未確認化）
・履歴を保持する元問題の削除
・4領域参照検査付きの分野削除
・ホーム画面（登録状況サマリー、進行中学習再開バナー、機能メニューカード）
・ハッシュルーティングによる機能別ページ切り替え（SPA）
・ダークモード切り替え機能（ヘッダー切替ボタン、OS設定自動検知、localStorage永続化）

2.2 未実装・今後の検討事項
・回答形式（5択／一問一答）による問題一覧の専用フィルター：未実装（対応状況の表示は実装済み）
・全データを消去する専用ボタン：未実装（全置換復元により代用可能）
・公開先の選定・配備：利用環境による

2.3 正式採用・確定した仕様
・完了リザルトは、科目ごとに最新10回（4科目合計最大40回）を保持し、上限超過時は古いものを自動削除する。
・苦手判定には、回答数と正答率による5段階基準を採用する（対象期間内の回答なし、データ不足、重点復習、復習推奨、比較的安定）。
・表示テーマはライト・ダークの2系統とし、ユーザーの選択状態をブラウザーに永続保持する。

3. システム構成・実行環境
3.1 アプリケーション構成
・単一のindex.htmlを基本構成とする。
・HTML・CSS・素のJavaScriptで実装する。
・npm・ビルドツール・外部ライブラリーを必要としない。
・アプリケーション専用のサーバー側処理を持たない。
・IndexedDBおよびlocalStorageに対応したブラウザーを必要とする。
・URLハッシュ（#home, #study, #analysis, #import, #manage, #backup, #fields）を利用したハッシュルーティングにより、単一ファイル内で独立した画面遷移を提供する。

3.2 配信方式
ローカルHTTPサーバー、または静的ホスティングによる利用を推奨します。
保存データはサイトのオリジンとブラウザープロファイルに紐づきます。異なるURLのオリジン・ブラウザー・プロファイル・端末では、自動的に同じ保存データを参照できません。

3.3 データ保全上の前提
・ブラウザーのデータ削除や端末故障等により、保存データが消失する可能性がある。
・index.htmlをコピーするだけでは、IndexedDBのデータを退避できない。
・全データの保全には、定期的にバックアップJSONを出力し、ブラウザー外に保存する。
・取り込み元の問題JSONも別途保管する。
・端末間のデータ移行は、バックアップの出力・復元によって行う。自動同期は行わない。

4. 画面構成
4.1 画面遷移方式（SPA）
単一のindex.html内に各画面コンテナ（.page）を配置し、URLハッシュに応じて該当画面のみを表示します。
画面上部には共通ヘッダー（サイトタイトル、メインメニュー、テーマ切り替えボタン）を常時表示します。

主な画面構成は次のとおりです。
1. ホーム画面 (#home)
2. 問題学習画面 (#study)
3. 苦手分析画面 (#analysis)
4. 問題JSON取り込み画面 (#import)
5. 登録済み問題管理画面 (#manage)
6. 全データ バックアップ・復元画面 (#backup)
7. 分野の削除画面 (#fields)

各機能画面の上部には「← ホームに戻る」リンクを設置し、迷わずホームへ復帰できるようにします。ブラウザーの「戻る」「進む」ボタン操作にも完全対応します。

4.2 ホーム画面 (#home)
以下を表示・操作できます。
・保存上の注意文（IndexedDB保存に関する案内）
・進行中学習の再開バナー：進行中の学習がある場合にのみ表示し、現在の進捗（例：第 3 問 / 全 10 問）と「学習を再開する」ボタンを提供
・現在の登録状況サマリー：登録分野数、登録問題数、5択出題可能数、一問一答出題可能数を表示
・機能メニューグリッド：各機能（学習、苦手分析、取り込み、管理、バックアップ、分野削除）の解説と移動ボタン

4.3 問題学習画面 (#study)
以下を表示・操作できます。
・学習条件設定：科目（初期値：電力）、回答形式（初期値：5択）、出題モード（初期値：10問）、分野（10問モード時のみ表示）
・出題可能数・不足数表示：出題可能な問題数、および不足している問題数を表示。不足時は開始ボタンを無効化
・学習開始ボタン：条件に従って問題を抽出し開始
・進行中の学習：問題番号、科目・分野・形式、共通条件（一問一答時）、問題文／判定文、選択肢、回答確定ボタン、中断・破棄ボタン
・確定後の解説表示：正誤判定（正解／不正解）、正答、解説、出典、法令基準日、次問移動／結果表示ボタン
・今回のリザルト表示：出題数、回答数、正解数、不正解数、正答率、全問題の詳細レビュー、「同じ条件でもう一度挑戦」ボタン
・過去リザルト履歴一覧：科目ごとに保存された最新10回のリザルトを一覧表示し、クリックで詳細を展開

4.4 苦手分析画面 (#analysis)
以下を表示・操作できます。
・分析科目の選択（初期値：電力。切り替えても学習画面の未確定選択は失われない）
・科目全体サマリー：直近回答数（最大100件）、正解数、不正解数、全体正答率
・分野別成績テーブル：分野名、苦手判定バッジ、合算成績、5択成績、一問一答成績
・「分析を更新」ボタン：最新データで再集計

4.5 問題JSON取り込み画面 (#import)
以下を表示・操作できます。
・問題JSONファイル選択（上限5 MiB、5,000問）
・「検査する」ボタン：形式検査および既存問題との比較
・取り込みプラン表示：新規、更新候補、同一内容、旧版の件数内訳、更新候補の個別選択チェックボックス
・「確認して一括登録」ボタン：確認ダイアログを経て同一トランザクションで登録

4.6 登録済み問題管理画面 (#manage)
以下を表示・操作できます。
・絞り込みフィルター：科目、分野、確認状態（未確認／確認済み／要修正）、出題対象（有効／無効）、問題文検索
・件数表示：登録済み件数、絞り込み結果件数、出題可能件数
・問題カード一覧（100件ずつの追加表示対応）
・各問題カード内の操作：
  - 確認状態・出題対象設定の変更と「設定を保存」ボタン
  - プレビュー展開（問題文、選択肢、正答、解説、一問一答データ、出典、基準日）
  - 問題内容のJSON直接編集欄と「編集内容を保存」ボタン
  - 「問題を削除」ボタン（確認ダイアログ付き）

4.7 全データ バックアップ・復元画面 (#backup)
以下を表示・操作できます。
・バックアップ出力：全6ストアの全データを1つのJSONファイルとしてダウンロード出力
・全置換復元：
  - バックアップJSONファイルの選択と「復元ファイルを検査する」ボタン
  - 復元プラン表示（分野、問題、学習、回答履歴、リザルト、設定の件数内訳）
  - 「全データを置き換えて復元する」ボタン（事前バックアップ検証、確認ダイアログ付き）

4.8 分野の削除画面 (#fields)
以下を表示・操作できます。
・削除対象分野の選択ドロップダウン
・「参照状況を検査」ボタン：問題、回答履歴、進行中学習、完了リザルトの4領域における参照件数を算出
・参照結果表示：内訳件数の表示。参照がある場合は削除不可。参照が0件の場合のみ「分野を削除する」ボタンを表示

5. データ仕様
5.1 保存領域
IndexedDB（データベース名：denkenQuizDB、バージョン：1）に、次の6つの保存領域を持ちます。
・fields：分野（keyPath: "id"、インデックス: subjectId）
・questions：登録済みの元問題（keyPath: "id"、インデックス: subjectId, fieldId, reviewStatus）
・sessions：進行中の学習（keyPath: "id"）
・answers：苦手分析用の回答履歴（keyPath: "sequence", autoIncrement: true、インデックス: id, subjectSequence, sessionQuestion）
・results：完了リザルト（keyPath: "sessionId"、インデックス: subjectId）
・settings：学習条件や学習記録の参照設定（keyPath: "key"）

また、UI表示テーマ（ライト／ダーク）はブラウザーの localStorage（キー: "denken-theme"）に保存します。

5.2 分野データ (fields)
・id：分野ID（文字列、前後の空白不可）
・subjectId：所属科目ID（theory, power, machine, regulation）
・name：分野名（文字列、200文字以内）

制約：
・分野IDは一意とする。
・1つの分野は1つの科目に所属する。
・同じ分野IDの名称更新に対応する。
・既存分野の所属科目を変更することはできない。

5.3 問題データ (questions)
・id：問題ID（文字列、前後の空白不可）
・revision：問題の版番号（1以上の安全な整数）
・subjectId：科目ID
・fieldId：分野ID（所属科目が一致すること）
・prompt：5択の問題文（空でない文字列）
・choices：5件の選択肢配列
・correctChoiceId：5択の正答となる選択肢ID
・explanation：5択の解説
・trueFalseContext：一問一答の共通条件（5択専用時はnull、一問一答対応時は文字列）
・reviewStatus：確認状態（unreviewed: 未確認, reviewed: 確認済み, needsFix: 要修正）
・enabled：出題対象設定（真偽値）
・references：出典・参考資料の文字列配列
・legalAsOf：法令等の基準日（YYYY-MM-DD形式の実在日付、またはnull）

5.4 選択肢・一問一答データ
各選択肢は以下を持ちます。
・id：問題内の選択肢ID（一意）
・text：5択で表示する選択肢本文
・trueFalse：一問一答用データ、またはnull
  - statement：判定する文章
  - isTrue：文章自体の真偽（真偽値）
  - explanation：その文章の真偽に関する解説

対応形式：
・5択専用：trueFalseContextがnull、全5選択肢のtrueFalseがnull
・5択・一問一答対応：trueFalseContextが文字列、全5選択肢のtrueFalseが完全に入力されている

5.5 出題対象条件
通常出題の対象は、以下の両方を満たす問題に限定します。
・reviewStatusが「reviewed（確認済み）」
・enabledが「true（有効）」
一問一答では、さらに一問一答対応データ（trueFalseContextおよび全選択肢のtrueFalse）を持つことが必要です。

5.6 学習記録 (sessions)
進行中の学習はブラウザー内に最大1件のみ保持します。
・id：学習セッションID
・revision：学習記録の版番号（更新ごとにインクリメント）
・createdAt：開始日時（ISO文字列）
・conditions：学習条件（subjectId, format, mode, fieldId）
・subjectName：科目名
・targetName：学習対象名（分野名または科目全体）
・questions：出題順に並んだ元問題の完全な複製配列
・selectedChoiceIds：一問一答で抽出した選択肢IDの配列（各問1件）
・answers：各問題の確定済み回答配列
・currentIndex：現在の表示位置（0始まり）

5.7 回答履歴 (answers)
確定した回答ごとに保存します。
・sequence：保存順（自動採番）
・id：回答ID（一意）
・sessionId：学習セッションID
・questionIndex：問題位置
・answeredAt：回答日時
・subjectId：科目ID
・fieldId：分野ID
・questionId：元問題ID
・questionRevision：回答時点の元問題版番号
・format：回答形式（choice5, trueFalse）
・mode：出題モード（random10, random100）
・choiceId：一問一答で提示した選択肢ID（5択時はnull）
・userChoice：利用者の回答（選択肢IDまたは真偽値）
・correctChoice：正答（選択肢IDまたは真偽値）
・isCorrect：正誤（真偽値）

保持上限：科目ごとに最新100件、4科目合計で最大400件を保持し、上限超過時は古いsequenceのレコードを自動削除します。

5.8 完了リザルト (results)
全問回答完了時に保存します。
・sessionId：学習セッションID
・completedAt：完了日時
・resultOrder：リザルト保存順（settingsで管理する連番）
・subjectId：科目ID
・conditions, subjectName, targetName, questions, selectedChoiceIds, answers
・totalCount：出題数
・answeredCount：回答数
・correctCount：正解数
・incorrectCount：不正解数
・scoreRate：正答率（小数第1位）

保持上限：科目ごとに最新10回（4科目合計最大40回）を保持し、上限超過時は古いレコードを自動削除します。

5.9 設定 (settings)
Key-Value形式で以下を保持します。
・currentSessionId：進行中の学習セッションID（未実行時はnull）
・lastSettings：最後に開始した学習条件（次回条件の初期復元用）
・lastResultSessionId：最新リザルトのセッションID
・resultOrderCounter：リザルト保存順の管理カウンター

6. 問題JSONの取り込み仕様
6.1 ファイル形式・上限
基本構造：
{
  "schemaVersion": 1,
  "fields": [],
  "questions": []
}
上限：容量 5 MiB、分野 1,000件、問題 5,000件。

6.2 既存問題との比較・更新
同じ問題IDが登録済みの場合は、版番号（revision）と内容を比較します。
・新しい版（revisionが大きい）：更新候補として表示し、利用者が選択した問題のみ更新。確認状態は「未確認」に戻す。
・同じ版・同じ内容：登録をスキップする（管理設定 reviewStatus, enabled の違いは内容比較から除外）。
・同じ版・異なる内容：取り込みを拒否する（revisionのインクリメントを促す）。
・古い版：登録をスキップする。

6.3 一括登録
分野と問題を同一トランザクション内で保存します。検査時点からデータが変更されていた場合は登録を中止し、再検査を求めます。

7. 問題管理仕様
7.1 一覧・検索・絞り込み
科目、分野、確認状態、出題対象の有効/無効、問題文の部分一致検索に対応します。一覧は問題ID順に100件ずつDOMに追加描画します。

7.2 プレビュー
各問題カードのアコーディオンから、5択の問題文・選択肢・正答・解説、一問一答の共通条件・全選択肢判定文・解説、出典、基準日を確認できます。学習履歴には影響しません。

7.3 管理設定の変更
確認状態（未確認／確認済み／要修正）および出題対象（有効／無効）を変更して保存できます。版番号は増加させず、保存直前に競合検査を行います。

7.4 問題内容のJSON直接編集
各カード内のJSON編集欄から、問題文・選択肢・正答・解説・科目・分野・一問一答データ・出典・基準日を直接編集できます。
・問題ID、版番号、確認状態、出題対象設定の直接変更は禁止。
・内容に変更があった場合のみ版番号を1増やし、確認状態を「未確認」へ自動更新する。
・内容に変更がない場合は版番号・確認状態を維持する。
・保存直前に競合検査を行い、別操作での変更を検知した場合は上書きを防止する。

7.5 元問題の削除
確認ダイアログを経て questions ストアから元問題のみを削除します。進行中の学習セッション、回答履歴、完了リザルト、複製された問題データは保持されます。

8. 学習・出題・採点仕様
8.1 学習条件と初期値
・科目：電力（初期値）
・回答形式：5択（初期値）
・出題モード：10問（初期値）
・分野：対象科目の登録分野（10問モード時のみ選択）
最後に開始した条件を settings に保存し、再読み込み時に自動復元します。

8.2 出題モードと不足判定
・10問モード：選択した分野から10問を元問題重複なしで抽出。
・100問モード：選択した科目全体から100問を元問題重複なしで抽出。
出題可能問題が不足している場合、出題可能数と不足数を赤字で明示し、開始ボタンを無効化します。

8.3 抽出・複製・固定
・Fisher–Yates法によるシャッフルで元問題を無作為抽出。
・抽出した問題をディープコピーして sessions に保存（元問題の改定・削除から完全独立）。
・一問一答では、各問題から選択肢1つを等確率（1/5）で抽出し、学習開始時に固定する。

8.4 回答確定・採点
・回答選択後、「回答を確定」を押すことで採点と進捗保存を同一トランザクションで実行。
・採点基準：
  - 5択：選択IDと correctChoiceId の一致
  - 一問一答：選択した真偽と choice.trueFalse.isTrue の一致
・確定後は回答の変更不可。正誤ボックス、正答、解説を表示。
・途中問題では「次の問題へ」、最終問題では「結果を見る」ボタンを表示。

8.5 途中再開と破棄
・ページ再読み込み時、進行中のセッションがあればその問題番号と状態（確定済みなら解説）を自動復元。
・進行中セッションがある状態で新しく学習を開始する場合は、確認ダイアログを表示して破棄・置き換えを承認する。
・「学習を中断・破棄」ボタンにより、セッションを明示的に終了可能（確定済み回答履歴は保持）。

9. リザルト仕様
9.1 完了処理
最終問題の回答確定と同時に完了リザルト（results）を作成・保存し、進行中セッションを削除します。
「結果を見る」ボタンを押すことで、今回リザルトの詳細画面へ遷移します。

9.2 表示内容
・科目名、対象名、形式、出題数、完了日時
・成績サマリー：出題数、回答数、正解数、不正解数、正答率（小数第1位）
・「同じ条件でもう一度挑戦」ボタン：同一条件で即座に新しい学習を開始
・全問題の詳細レビュー：各問の問題文、あなたの回答、正答、正誤判定、解説、出典、基準日

9.3 過去リザルト履歴
科目ごとに最新10件を保存順の新しい順でテーブル表示。各行の「詳細」ボタンから過去のリザルト詳細を閲覧できます。

10. 苦手分析仕様
10.1 集計対象
選択した科目全体の answers テーブルから、最新順（sequence降順）で最大100回答を抽出して母集団とします。
・5択・一問一答を合算。
・10問・100問モードを合算。
・同一問題への重複回答、途中終了した学習の確定済み回答も含む。
・未確定の選択は含まない。

10.2 表示項目と苦手判定基準
分野合算の回答数および正答率に基づき、以下の5区分で判定ラベルを付与します。
・0回答：「対象期間内の回答なし」（灰色バッジ、正答率は「回答なし」と表示）
・1〜4回答：「データ不足」（灰色バッジ）
・5回答以上、正答率 60％未満：「重点復習」（赤色バッジ）
・5回答以上、正答率 60％以上80％未満：「復習推奨」（黄色バッジ）
・5回答以上、正答率 80％以上：「比較的安定」（緑色バッジ）
※判定には丸め前の値を使用し、表示は小数第1位とします。形式別（5択、一問一答）には判定ラベルを付けず、正答率を表示します。

10.3 表示順
1. 判定可能な分野（正答率の低い順。同率の場合は分野名、分野ID順）
2. データ不足の分野
3. 対象期間内の回答がない分野
※現在の分野一覧にない過去の分野IDも除外せず表示します。

11. バックアップ・復元仕様
11.1 対象・形式
全6領域（fields, questions, sessions, answers, results, settings）を対象とします。
{
  "backupType": "denken-quiz-full",
  "backupVersion": 1,
  "databaseVersion": 1,
  "exportedAt": "ISO日時",
  "data": { fields, questions, sessions, answers, results, settings }
}
上限：ファイル容量 100 MiB、分野 10,000件、元問題 50,000件、セッション 1件、回答履歴 400件、リザルト 40件、設定 4件。

11.2 出力
全領域を同一読み取りトランザクションで取得し、バリデーション通過後にファイル「denken-backup-YYYYMMDD-HHmmss.json」としてダウンロードします。直近出力データのフィンガープリントをメモリに記憶します。

11.3 復元前検査と全置換復元
・問題取り込み用JSON（schemaVersion: 1）の誤指定を拒否。
・データ構造、件数・容量上限、ID重複、整合性を検査。
・安全機構：復元前に「現在の全データのバックアップ出力」が完了しており、検査時からデータ変更がないことを検証した上で、全置換確認ダイアログを経て6ストアの全クリア＆書き込みを単一トランザクションで実行します。

12. 削除仕様
12.1 元問題の削除
問題カードから確認ダイアログを経て削除。questions から元問題のみを削除し、過去の学習記録や回答履歴は保持します。

12.2 分野の削除
以下の4領域から参照されている分野は削除できません。
1. 登録済み問題（questions）
2. 回答履歴（answers）
3. 進行中学習の条件または問題（sessions）
4. 完了リザルトの条件または問題（results）
参照検査結果の内訳件数を表示し、参照が0件の場合のみ削除を実行できます。

13. 整合性・競合・エラー処理
13.1 トランザクション
読み取り・検査・書き込みを可能な限り同一トランザクション内で実行し、整合性を担保します。
13.2 競合防止
表示時点のデータと現在のデータを比較し、別操作での変更を検知した場合は上書きを防止します。
13.3 別タブ通知
BroadcastChannel（denkenQuizDB-catalog）を利用し、問題データの更新を別タブに通知します。

14. 非機能要件・UI仕様
14.1 安全性
問題文や解説はテキストノードとして描画し、XSSを防止します。

14.2 操作性・アクセシビリティ
・PC・スマートフォンの画面幅に対応するレスポンシブデザイン。
・キーボード操作、フォーカスリング表示、aria属性による状態通知に配慮。
・SPA構成により不要なスクロールや画面のちらつきを排除。

14.3 表示テーマ（ダークモード対応）
・CSS変数によるライトテーマおよびダークテーマの一元管理。
・ヘッダー右上のトグルボタン（🌙 ダーク / ☀️ ライト）によりワンクリックで切り替え可能。
・初回アクセス時は OS／ブラウザーのカラーテーマ設定（prefers-color-scheme: dark）を自動検知。
・ユーザーが選択したテーマは localStorage（キー: denken-theme）に永続保存され、次回アクセス時も自動適用。
・ダークモード時は深みのあるスレートネイビー（#0f172a / #1e293b）と落ち着いたライトグレー文字を採用し、長時間の学習でも目の負担を軽減。

15. 受け入れ確認項目
以下を実装済みかつ動作確認済みとします。
・JSON取り込み、版番号比較、一括登録、タイポなし
・出題不足時の開始無効化・不足数表示
・元問題重複なし抽出、複製問題による元データ独立
・一問一答の等確率抽出と真偽採点
・二重回答防止、途中再開、リザルト保存と上限管理
・最新100回答抽出による5区分苦手分析
・全領域バックアップ出力、復元前検査、事前出力検証付き全置換復元
・問題内容のJSON編集（版番号インクリメント・未確認化）
・元問題削除後の学習継続、4領域参照検査付き分野削除
・ホーム画面と各機能画面のSPA遷移、ブラウザー履歴対応
・ダークモード切り替えと設定永続化

16. 運用・利用案内
・ローカルのWebブラウザーで index.html を開くだけで即座に全機能を利用可能。
・テスト用として、水力発電の1問データ（test.json）および10問学習データ（sample_10_questions.json）を同梱。
・データ保全のため、定期的に「バックアップ・復元」画面から全データJSONを出力して保管することを推奨。
